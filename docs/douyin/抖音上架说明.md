## 1. 账号、AppID 与需要填 ID 的地方

1. 打开 https://developer.open-douyin.com/ → 登录 → 控制台 → 「小游戏」→「创建小游戏」，填写名称、联系人并同意协议。创建后在小游戏详情页「开发 → 开发设置」查看 **AppID**（`tt` 开头）。
   文档：https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/guide/minigame/improve-information
2. **所有 ID 只在一个文件里填**：`src/config/PlatformConfig.js`（文件顶部有 TODO 说明）

   ```js
   douyin: {
     appId: 'TODO_填写抖音小游戏AppID',            // ← 改成 ttxxxxxxxxxxxxxxxx
     rewardedAdUnitId: 'TODO_填写激励视频广告位ID', // ← 流量主开通后新建激励视频广告位得到的 ID；留着 TODO = 隐藏看视频按钮、复活改为免费「再试一次」
     softwareCopyrightNo: '',                       // ← 软著登记号，例如 '2026SR0123456'（显示在启动画面）
     ...
   }
   ```
3. 改完执行 `npm run build:douyin`，会重新生成 `dist-douyin/` 并同步到 `douyin/`（AppID 会写进 `douyin/project.config.json`）。
   - 没装 Node 的话也可以：只改 AppID 时，在开发者工具导入项目时直接填 AppID 即可（会覆盖 project.config.json 里的 `testappid`）；广告位 ID 和软著号是打包进 `game.js` 的，必须重新构建（发给我改也行）。

## 2. 资质与合规

> **重要：主体 ≠ 署名。** 软著的著作权人、隐私政策里的运营者、ICP 核准主办单位、流量主结算账户，**都必须是抖音开发者账号上实名认证的真实法律主体**（公司全称或个人）。游戏里的「出品：狸猫」只是品牌/出品署名，**不能**用来申请软著或填写隐私政策主体。

### 2.1 软著（必需）
- 小游戏上线必须提供**计算机软件著作权登记证书**；**同一软著只能给一款在线小游戏使用**。
- **小游戏名称须与软著登记的软件名称一致**（全称可忽略"app""游戏软件"等后缀），所以软著建议登记为「美少女合成」或「美少女合成游戏软件」。
- **著作权人须与开发者平台的主体名称完全一致**，不一致需提交盖鲜章的授权书。游戏内显示的「出品：狸猫」只是署名，不影响资质；但软著、隐私政策、ICP 核准的主体都要用开发者账号的认证主体。
- 拿到登记号后填 `PlatformConfig.douyin.softwareCopyrightNo`，启动画面会自动显示「著作权登记号：…」（内容规范 11.1 要求在开始画面标明）。
- 文档：资质规范 https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/operation1/norms/credential-norms-for-mini-game

### 2.2 是否需要版号？——**不需要**（本游戏只有激励广告，没有内购/虚拟支付）
- 有"广电总局/国家新闻出版署版号批文"的游戏可直接做 ICP 核准；**没有版号的小游戏先完成「小游戏备案」，通过后再开放 ICP 核准入口**。所有小游戏都必须完成 ICP 核准才能上架。
- 如果以后要做**内购（虚拟支付）**，则需要版号。
- 文档：ICP 核准指引 https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/guide/minigame/icp/icp-filings
  （"无版号小游戏 ICP 核准入口将在小游戏备案申请审核通过后开放"；"无版号小游戏需另行完成小游戏备案"）

### 2.3 小游戏备案 → ICP 核准
1. 基础信息（名称、软著、详细介绍等）审核通过后，平台会提交「小游戏备案」（文档里也叫市宣备案）。**详细介绍会用于备案**，所以要写实、不要自夸（`上架资料/商店文案.md` 已按此写好）。
2. 备案通过后：控制台「总览 → ICP 核准 → 完善信息」，按页面填写主办单位（营业执照）、主体负责人（多数省份要求法定代表人，上海要求法定代表人）、小程序负责人（人脸核验）等；平台审核 1–3 个工作日 → 工信部短信核验（24 小时内）→ 管局审核。
3. 小程序备注不得涉及盈利信息；营业执照经营范围若命中「文化」等前置审批关键字但实际不涉及，需按页面提示备注或上传承诺书。

### 2.4 游戏内必须展示的信息（已在游戏里实现）
| 要求 | 出处 | 游戏中的实现 |
| --- | --- | --- |
| 开始前全文登载《健康游戏忠告》 | 内容规范 11.2 | 启动/加载画面显示全文（所有平台） |
| 开始画面标明著作权登记号 | 内容规范 11.1 | 启动画面显示（填 `softwareCopyrightNo` 后） |
| 适龄提示、防沉迷等未成年人保护措施 | 内容规范 11.3 | 启动画面显示「适龄提示：8+」；另需在控制台提交适龄分段与说明；实名/防沉迷由抖音平台执行 |
| 不得出现现金符号、赌博、低俗着装/性暗示文案等 | 内容规范 2.7 / 5 / 12 | 已自查；注意第 7 节"风险提示" |
- 文档：内容规范 https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/operation1/norms/content-norms-for-mini-game
- 适龄提示：控制台「设置 → 基础设置」中提交适龄年龄分段和说明（建议 8+，理由：无暴力血腥、无付费、无社交）。

### 2.5 隐私政策
- 在控制台「设置 → 基础设置 → 小游戏隐私政策」中完善，发布后平台会向玩家展示；协议里的小游戏名称、主体名称自动取控制台信息，不能自定义。
- 草稿见 `上架资料/隐私协议草稿.md`（本游戏不收集个人信息；只有本地存档、录屏（仅游戏画面）、激励广告、启动场景值）。草稿里的【开发者主体名称】必须替换成开发者账号认证的真实主体全称，不能写「狸猫」。

### 2.6 基础信息与类目
- 名称 4–20 字；简介 10–60 字；详细介绍 120–300 字；图标 png/jpg 且**不能是圆角图标**、不能有 NEW/HOT 等角标。
- 类目：**休闲 → 益智 → 合成**；题材：二次元；画风：可爱卡通（或日韩卡通）。
- 文档：基础信息审核规范 https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/operation1/norms/game-info-audit
- 全部文案与图片：`上架资料/商店文案.md`、`上架资料/screenshots/`
  - 1080×1920 竖屏截图 5 张（菜单、游戏中、看视频复活、结算分享、胜利）
  - 342×600 搜索结果页竖图 3 张

## 3. 流量主与激励视频广告

1. **开通时机**：在小游戏后台「商业化 → 流量主」申请。流量主准入条件是小游戏**已上线**（企业主体）；个人主体还要求**已上线且 DAU≥50**（能力详情页：https://developer.open-douyin.com/capacity-center-page/capacity-detail/7179893068693389370 ，以后台页面实际显示为准）。所以**首个版本只能不带广告上线**。
2. **没有广告位 ID 时游戏的行为（首发版本）**——`rewardedAdUnitId` 保持 `TODO_…` 或留空即可：
   - 所有「看视频」按钮全部隐藏；
   - 堆满时的复活变成**免费的「再试一次」**（每局 1 次，同样清掉警戒线附近及以上的角色后继续；第二次堆满直接结算）；
   - 「整理次数用完后看视频 +1」隐藏（整理次数用完就是用完）；
   - 侧边栏复访奖励（下一局 +1 整理）照常可用。
   - 如不想要免费再试一次，把 `PlatformConfig.douyin.freeReviveWithoutAds` 改为 `false`（堆满直接结算）。
3. **开通流量主之后**：「流量主 → 广告管理」→ 新建**激励视频广告**，得到广告位 ID → 填 `PlatformConfig.douyin.rewardedAdUnitId` → `npm run build:douyin` → 上传新版本。无需改任何代码，游戏自动切换为：
   - **看视频复活**：堆满时弹出，每局 1 次；看完复活，中途关闭不给奖励（免费「再试一次」随之取消）；
   - **看视频 +1 整理**：整理次数用完后整理按钮显示「▶」，每局 1 次。
   两个位置用同一个广告位 ID 即可（代码里按 placement 区分统计）。
4. 实现细节（符合文档要求）：广告实例全局单例；始终监听 onError（失败时 toast 提示，不发奖励）；onClose 以 `count`（缺省时 `isEnded`）判断是否看完；广告播放时游戏暂停。广告返回 1004 时平台会自动拉起录屏/好友分享作为替代，分享成功同样回调 `count==1`，代码无需改动。
5. 文档：tt.createRewardedVideoAd https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/develop/api/javascript-api/ads/tt-create-rewarded-video-ad

## 5. 导入、预览、上传、审核

1. 下载安装 **抖音开发者工具**（文档首页有下载入口）。
2. 「导入项目」→ 选择 `美少女合成\抖音小游戏`（即本 `douyin/` 目录）→ 填入 AppID（或使用已写入 project.config.json 的 AppID）→ 打开。
   - `上架资料/` 和 `*.md` 已在 `project.config.json` 的 `packOptions.ignore` 中忽略，不会算进包体、也不会上传。
3. 模拟器里检查：启动画面（健康游戏忠告/适龄提示）→ 分包加载进度 → 菜单 → 开局、投放、合成、音效与语音。
4. 侧边栏复访测试：开发者工具「添加编译模式」选场景值 **021036**（或在模拟器里点「奖励 → 去侧边栏」调起模拟侧边栏再点回游戏），应看到「领取奖励」。
5. 「预览」→ 抖音扫码**真机测试**（重点：iPhone 和 Android 各一台；声音、录屏分享、侧边栏入口、前后台切换；填了广告位后测看视频复活/+1 整理）。
6. 「上传」→ 填版本号（建议 1.8.0）和备注 → 控制台「版本管理」中提交审核 → 审核通过后发布。
7. 首次提审前确认：基础信息审核已通过、自审自查报告已确认、隐私政策已完善、适龄提示已提交；小游戏备案/ICP 核准未完成时可以先提审版本，但**ICP 核准通过前不能上架**。

## 6. 语音授权（法人 + 抖音 + 广告变现）复核结论

游戏发行物中**只有生成好的 mp3，不包含任何语音模型**。AivisHub 上的模型授权本身都允许法人商用、无需事先联系；但有 3 家权利方另有指南，要求**企业使用前联系**。没有擅自替换，需要你决定：

| 模型（使用等级） | 授权 | 法人商用、无需联系？ | 说明 |
| --- | --- | --- | --- |
| リダ / Lida（Lv4, 8） | 作者自定授权 | ✅ 是 | "商用・非商用問わずご利用いただけます"；**必须署名**「リダ」或「Lida」+ URL（游戏「制作人员」已显示）；禁止二次配布/转让（指模型，我们不分发模型）、训练、暴力/性用途；作者声明授权可能变更，上架前再确认一次 |
| 黄金笑_T2（Lv6） | Tαkoe 项目利用规约 | ✅ 是 | 明确允许法人利用、商用；**必须著作权表示**「Tαkoe:AivisSpeech:黄金笑」（已显示）；禁止赌博相关、损害角色形象 |
| コハク（Lv1, 9）、まお（Lv7, 10, 11） | ACML 1.0（Trippy 官方发布） | ⚠ 需确认 | ACML 允许法人商用；但オズチャット二次創作ガイドライン第4条要求"法人または営利事業者"事先联系 https://tr1ppy.com/contact （该指南针对其角色的二次创作；我们只用声音、角色形象为原创，属解释空间） |
